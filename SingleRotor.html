The Bombe: finding a plausible machine state from a crib

Start with a guessed plaintext fragment (a crib), not its position. The program slides it across the ciphertext, keeps only positions that can be Enigma-valid, then tests rotor windows and plugboard consequences.

How the three components work

This single-rotor demonstrator separates permanent wiring from the contact engaged at the current rotor position.

Plugboard

The plugboard is a fixed, bidirectional set of letter swaps. A cable A–M makes A become M and M become A; an unconnected letter stays itself. The signal passes through it on both the outward and return paths.

Rotor

A rotor contains 26 permanent internal wires linking one contact face to the other. Stepping rotates the entire rotor, so the current engaged contact changes, but its internal wiring table never changes. The return path uses the same wires in reverse.

Reflector

The reflector is fixed and does not step. Its 26 contacts are wired in pairs, sending the signal back through the rotor. This makes the same configuration usable for encryption and decryption.

Window, stepping, and the engaged contact

The window letter is a position marker, not a new rotor wiring table. In this app, each A–Z character steps the rotor before it is processed; a space or punctuation mark does not. Stepping changes which fixed-frame letter meets which rotor contact, while the permanent rotor wires remain unchanged.

Two Enigma properties

With the same initial window, stepping rule, plugboard, rotor, and reflector, the same path decrypts what it encrypts. Standard Enigma also never sends a letter to itself. That rule immediately rejects a crib alignment containing the same plaintext and ciphertext letter at one position.

Modern ciphertext-only attack

A modern attack can avoid a crib: decrypt under each rotor state with an empty plugboard, rank the outputs by the Index of Coincidence (IC), then optimize the fixed plugboard with n-gram language scores. IC is only a prefilter; readable text and the final n-gram score decide the candidate.

Bombe terms: crib, menu, loop, and stop

A crib is a guessed plaintext fragment. Standard Enigma cannot encipher a letter as itself, so an alignment with any identical plaintext/ciphertext letter is impossible. A menu is the graph made by linking each crib letter to the ciphertext letter below it; a loop is a closed route in that graph. For example, THEOLDMILL over DYZHATNHPT contains T–D and D–T, giving the loop T–D–T. A stop is a rotor setting and plugboard hypothesis that produces no contradiction in this menu; it is a candidate for checking, not a complete recovered key.

Provisional text, language check, and word clues

A provisional text applies the plugboard facts already inferred, while letters still unknown are temporarily left unchanged. It is therefore a preview, not a final decryption. In D, a four-letter English-frequency model ranks these previews. In E, recognizable word clues are tested one at a time to infer further plugboard facts; an exact word and an “≈” near word are clues, not confirmation.

Scope of this demonstrator

This app uses one stepping rotor, reflector B, and a limited plugboard to make the signal path and constraint logic visible. Its Bombe tab is a software menu-constraint demonstration. It does not reproduce the historical multi-rotor machines, full daily-key recovery procedure, or Bombe hardware. The D and E language steps are modern teaching aids added by this app.
